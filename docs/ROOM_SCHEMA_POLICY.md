# Lexora Service — политика локальной схемы данных

## Текущая версия схемы
Room database schema version: 2.

## Правила
- Изменение существующей production-схемы выполняется только через явную Migration.
- `fallbackToDestructiveMigration()` в production-конфигурации запрещён.
- Архивирование бизнес-значимых сущностей предпочтительнее физического удаления.
- Каждая изменяемая офлайн-сущность содержит состояние синхронизации.
- Аудит хранится отдельными событиями и не подменяется полем `updatedAt`.
- До подключения сервера `PENDING_*` означает локальное изменение, ожидающее синхронизации.
